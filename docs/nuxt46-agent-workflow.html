TL;DR

Nuxt 4.6 / Nuxt CLI v4 讓 coding agent 少走三段冤枉路：查到錯誤版本的文件、要工程師手動整理錯誤訊息、自己再開一個 dev server 搶 port。升級後只要再做兩件事：用 shell 腳本檢查環境，並把 skill 放進 repo，讓 agent 知道要怎麼用這些指令。

為何是現在

  • 升級本來就在計畫中：b2c-web 在 4.5.1 踩到 _routeRulesMatcher 初始化順序 bug（nuxt/nuxt#35982），官方已在 4.6.0 修復；PR #3376 已改成 4.6 相容寫法。
  • Nuxt 3 已 EOL（2026-07-31）：agent 的訓練資料裡仍有大量 Nuxt 3 寫法，回答時容易混用版本。
  • 只升級還不夠：agent 不會自己去用 nuxt docs、nuxt curl，需要 skill 明確告訴它。

四個功能實測

四個功能在 Nuxt 4.6.1 + @nuxt/cli 4.0.1 上都能直接使用（只有 nuxt task 需要開啟 nitro.experimental.tasks）。以下行為都是實際執行的結果，不是轉述官方文章。

功能指令 / 入口實測行為解決的 agent 痛點
依版本搜尋文件nuxt docs "<query>" --no-open首次下載並索引 4.6.1 文件（217 頁），快取在 ~/.cache/nuxt/docs/；之後每次查詢約 0.3 秒，回傳前 7 筆相符頁面與連結拿 Nuxt 2/3 寫法回答
錯誤畫面 Copy error瀏覽器錯誤畫面右上角下拉三種格式：Markdown、Copy prompt for an agent（約 1 KB）、structured JSON（約 8 KB）工程師手動整理 stack trace
Dev server lock.nuxt/nuxt.lock + nuxt dev記錄 pid、port、URL、interactive；第二個 nuxt dev 依原本的 server 是誰開的決定讓出或接手搶 port、污染 .nuxt/
對 dev server 發 requestnuxt curl <path>、nuxt task run <name>自動讀 lock 找到 URL；JSON 自動排版；沒有執行中的 server 時明確報錯猜錯 port、無法自行驗證

Agent 修 bug 的閉環

Copy prompt for an agent 的內容

複製出的 prompt 開頭是一句任務指示，後面依序是錯誤類型與訊息、component trace、含行號的原始碼片段、stack、request、route、執行環境：

Help diagnose this error. Trace the root cause in the source, explain the failure, and propose the smallest appropriate fix. Verify the fix against the relevant behaviour.

## Error: TypeError
Cannot read properties of undefined (reading 'localStorage')

Component trace: <nuxt-root> › <app> › <NuxtPage> › <RouterView> › <RouteProvider> › <broken>
./app/pages/broken.vue:5:27

**Request** method: GET / url: /broken / status: 500
**Route** path: /broken / name: broken
**Environment** runtime: node 22.22.0 / my-bad: 0.2.11
  • SSR 時 server bundle 會把 window 替換成 undefined，所以錯誤是 TypeError，而不是 ReferenceError: window is not defined。
  • 這類 bug 能完全通過 nuxt typecheck，必須用 nuxt curl 檢查 SSR 輸出。

Dev server lock 的接手規則

實測結果與 @nuxt/cli 4.0.1 原始碼（takeover 模組）一致：

已在執行的 server誰再開 nuxt dev預設結果
工程師在終端機開的（interactive: true）agent（非 TTY）拒絕，印出既有 URL，工程師的 server 不受影響
agent 開的（interactive: false）agent自動接手：SIGTERM 舊的、沿用同一個 port
任何工程師在終端機詢問要接手還是中止
任何帶 --port 且與既有 port 不同不接手，仍因 lock 結束

--takeover 強制接手，--no-takeover 永不接手。NUXT_IGNORE_LOCK=1 可繞過 lock，但官方標示 unsupported。

導入步驟

1. 升級

  • Node.js 符合 ^22.22.3 || ^24.15.0 || >=26.0.0：本地 .nvmrc、CI runner、Dockerfile base image 都要對齊
  • 確認沒有使用 Nuxt 2 / @nuxt/bridge（4.6 起不再支援）
  • 在 feature branch 執行 npx nuxt upgrade --dedupe（會連帶升到 Nuxt CLI v4）
  • 本地跑首頁、目的地頁、商品頁，對照 SIT 行為

2. 檢查環境並安裝 skill

# monorepo 請傳入 Nuxt app 目錄
bash nuxt46-agent-setup.sh apps/main                  # 只檢查，不修改任何檔案
bash nuxt46-agent-setup.sh apps/main --install-skill  # 檢查 + 寫入 .claude/skills/nuxt46-agent-workflow/SKILL.md

3. 收集回饋

  • 一週後在週會確認：agent 有沒有用 nuxt curl 自行驗證、還有沒有搶 port 的情況

# Nuxt 4.6 Agent 工作流程

> Requires: Nuxt 4.6.x / Nuxt CLI (`@nuxt/cli`) 4.x / Node.js ^22.22.3 || ^24.15.0 || >=26.0.0
> 實測環境：Nuxt 4.6.1、@nuxt/cli 4.0.1。

## 0. 先確認版本

執行 `npx nuxt --version` 與 `npx nuxt info`。若 Nuxt < 4.6 或 CLI < 4，本 skill 的 `nuxt docs` / `nuxt curl` / `nuxt task` / dev lock 都不存在，改回一般流程並告知使用者。

## 1. 查文件：一律用專案安裝的版本

```bash
npx nuxt docs "<關鍵字>" --no-open
```

- 結果以專案安裝的 Nuxt 版本為準；首次執行會下載索引到 `~/.cache/nuxt/docs/`，之後約 0.3 秒。
- 禁止依賴記憶中的 Nuxt 2 / Nuxt 3 寫法（皆已 EOL）。
- 一定要加 `--no-open`，否則會嘗試開瀏覽器。

## 2. Dev server：先沿用，不要搶

1. 先檢查是否已有 server：`npx nuxt curl / -I`。回 HTTP 狀態即代表已有 server，直接沿用。
2. 需要自己啟動時：`npx nuxt dev --no-tui`，**不要加 `--port`**（指定不同 port 會跳過接手機制）。
3. 若輸出含「It was started interactively」：那是工程師在終端機開的 server。**禁止**加 `--takeover`，改用訊息中的既有 URL。
4. 禁止設定 `NUXT_IGNORE_LOCK=1`（官方標示 unsupported，兩個 server 會同時寫入 `.nuxt/`）。

接手規則（`.nuxt/nuxt.lock` 決定）：

| 既有 server | 你（非 TTY）再開 `nuxt dev` | 結果 |
| --- | --- | --- |
| 工程師在終端機開的（`interactive: true`） | 預設 | 拒絕，印出既有 URL |
| agent 開的（`interactive: false`） | 預設 | 自動接手（SIGTERM 舊的、沿用 port） |
| 任何 | 帶不同 `--port` | 不接手，因 lock 結束 |

## 3. 驗證修改：一定要打 SSR 輸出

```bash
npx nuxt curl <path> -i          # 看 HTTP 狀態與 headers
npx nuxt curl "/api/xxx?q=1"     # JSON 會自動排版
npx nuxt task list               # 需 nitro.experimental.tasks = true
npx nuxt task run <name> --payload.key=value
npx nuxt typecheck
```

- `nuxt curl` 會讀 `.nuxt/nuxt.lock` 找到執行中的 server，不需指定 port。
- **`nuxt typecheck` 抓不到 SSR 階段存取 `window` / `document` 的錯誤**，必須以 `nuxt curl <path> -i` 確認回 200。
- 修完回報時附上 `nuxt curl` 的狀態碼作為證據。

## 4. 處理錯誤畫面貼來的 prompt

使用者貼上以 `Help diagnose this error.` 開頭的內容，是 Nuxt 錯誤畫面「Copy prompt for an agent」產生的，已含：錯誤類型與訊息、component trace、`檔案:行:欄`、原始碼片段、stack、request、route、runtime。

處理順序：依 `檔案:行:欄` 定位 → 用 `nuxt docs` 查正確用法 → 最小修改 → `nuxt curl` 驗證 → `nuxt typecheck`。

已知陷阱：SSR 時 server bundle 會把 `window` 替換成 `undefined`，所以錯誤訊息是 `TypeError: Cannot read properties of undefined`，而非 `ReferenceError: window is not defined`。修法是把瀏覽器 API 移到 `onMounted`，或以 `import.meta.client` 判斷。

## 5. 環境注意事項

- 在 TTY 下首次執行 `nuxt dev` 會停在 `@nuxt/telemetry` 詢問；可設 `NUXT_TELEMETRY_DISABLED=1`。
- `typescript@7` 與 `vue-tsc` 不相容（`ERR_PACKAGE_PATH_NOT_EXPORTED`），需 `typescript@^5`。
- monorepo 下指令需在 Nuxt app 目錄執行，或加 `--cwd <app 目錄>`（此行為尚未實測）。
- structured JSON 錯誤格式含絕對路徑與原始碼，不得貼到公開頻道。

環境檢查 Shell

對任何 Nuxt 4.6+ 專案執行：檢查 Node、套件管理工具、Nuxt / CLI / TypeScript 版本、telemetry 設定、dev server 狀態與 nuxt docs 是否可用。預設只讀取不修改；加上 --install-skill 才會寫入 skill（已存在則不覆蓋）。不會啟動或終止任何程序。

nuxt46-agent-setup.sh
#!/usr/bin/env bash
# nuxt46-agent-setup.sh — 檢查 Nuxt 4.6 agent 工作流程的環境，並（選用）安裝 Claude Code skill
# Requires: Nuxt 4.6.x / @nuxt/cli 4.x / Node.js ^22.22.3 || ^24.15.0 || >=26.0.0
#
# 用法：
#   bash nuxt46-agent-setup.sh [Nuxt app 目錄]                  # 只檢查，不修改任何檔案
#   bash nuxt46-agent-setup.sh [Nuxt app 目錄] --install-skill  # 檢查 + 安裝 skill 到 .claude/skills/
set -euo pipefail

ok()   { printf '\033[1;32m✔ %s\033[0m\n' "$1"; }
warn() { printf '\033[1;33m! %s\033[0m\n' "$1"; WARNINGS=$((WARNINGS + 1)); }
fail() { printf '\033[1;31m✖ %s\033[0m\n' "$1"; exit 1; }
WARNINGS=0

APP_DIR="."
INSTALL_SKILL=0
for arg in "$@"; do
  case "$arg" in
    --install-skill) INSTALL_SKILL=1 ;;
    -h|--help) sed -n '2,8p' "$0"; exit 0 ;;
    *) APP_DIR="$arg" ;;
  esac
done
cd "$APP_DIR"
ls nuxt.config.* >/dev/null 2>&1 || fail "$(pwd) 找不到 nuxt.config.*，請傳入 Nuxt app 目錄（monorepo 例：apps/main）"

# 1. Node.js 版本
command -v node >/dev/null 2>&1 || fail "找不到 node，請安裝 Node.js 24 LTS（nvm install 24）"
NODE_OK=$(node -e '
  const [M, m, p] = process.versions.node.split(".").map(Number);
  const ok = (M === 22 && (m > 22 || (m === 22 && p >= 3))) || (M === 24 && m >= 15) || M >= 26;
  console.log(ok ? "1" : "0");
')
if [ "$NODE_OK" = "1" ]; then ok "Node.js $(node -v)"
else warn "Node.js $(node -v) 不符合 ^22.22.3 || ^24.15.0 || >=26.0.0（pnpm/npm 預設不會擋，但非官方支援）。nvm install 24 && nvm use 24"
fi

# 2. 套件管理工具（依 lockfile 判斷，往上找到 monorepo 根目錄）
find_up() { local d; d=$(pwd); while [ "$d" != "/" ]; do [ -e "$d/$1" ] && { echo "$d"; return 0; }; d=$(dirname "$d"); done; return 1; }
if   find_up pnpm-lock.yaml >/dev/null; then PM="pnpm"
elif find_up yarn.lock >/dev/null;      then PM="yarn"
else PM="npm"; fi
command -v "$PM" >/dev/null 2>&1 || fail "專案使用 $PM，但找不到指令"
ok "套件管理工具：$PM $($PM -v)"

# 3. 讀取已安裝套件版本（不經 exports，直接讀 package.json）
pkg_version() {
  node -e '
    const fs = require("fs"), path = require("path");
    let dir = process.cwd();
    while (true) {
      const f = path.join(dir, "node_modules", process.argv[1], "package.json");
      if (fs.existsSync(f)) { console.log(JSON.parse(fs.readFileSync(f, "utf8")).version); process.exit(0); }
      const up = path.dirname(dir); if (up === dir) process.exit(0); dir = up;
    }
  ' "$1"
}
ver_ge() { node -e 'const a=process.argv[1].split(".").map(Number),b=process.argv[2].split(".").map(Number);for(let i=0;i<3;i++){if((a[i]||0)!==(b[i]||0)){process.exit((a[i]||0)>(b[i]||0)?0:1)}}process.exit(0)' "$1" "$2"; }

NUXT_V=$(pkg_version nuxt)
[ -n "$NUXT_V" ] || fail "找不到已安裝的 nuxt，請先執行 $PM install"
if ver_ge "$NUXT_V" 4.6.0; then ok "Nuxt $NUXT_V"
else fail "Nuxt $NUXT_V < 4.6.0，請先在 feature branch 執行：npx nuxt upgrade --dedupe"; fi

CLI_V=$(npx --no-install nuxt --version 2>/dev/null | grep -Eo '[0-9]+\.[0-9]+\.[0-9]+' | head -1 || true)
if [ -n "$CLI_V" ] && ver_ge "$CLI_V" 4.0.0; then ok "@nuxt/cli $CLI_V"
else warn "@nuxt/cli 版本 ${CLI_V:-未知} < 4，nuxt docs / curl / task 不可用。執行 npx nuxt upgrade --dedupe"; fi

# 4. TypeScript 與 vue-tsc 相容性
TS_V=$(pkg_version typescript)
if [ -z "$TS_V" ]; then warn "未安裝 typescript；nuxt typecheck 需要 $PM add -D typescript@^5 vue-tsc"
elif [ "${TS_V%%.*}" -ge 7 ]; then warn "typescript $TS_V 與 vue-tsc 不相容（ERR_PACKAGE_PATH_NOT_EXPORTED），請改用 typescript@^5"
else ok "typescript $TS_V"; fi

# 5. Telemetry 詢問
if [ "${NUXT_TELEMETRY_DISABLED:-}" = "1" ]; then ok "NUXT_TELEMETRY_DISABLED=1"
else warn "未設定 NUXT_TELEMETRY_DISABLED=1：首次在終端機執行 nuxt dev 會停在 telemetry 詢問（回答一次即可）"; fi

# 6. Dev server 狀態（只讀取，不啟動、不終止任何程序）
if [ -f .nuxt/nuxt.lock ]; then
  if npx --no-install nuxt curl / -I >/dev/null 2>&1; then
    ok "偵測到執行中的 dev server：$(node -e 'const l=JSON.parse(require("fs").readFileSync(".nuxt/nuxt.lock","utf8"));console.log(l.url+" (pid "+l.pid+(l.interactive?", 終端機啟動":", 非互動啟動")+")")')"
  else ok "有 .nuxt/nuxt.lock 但 server 未在執行（下次 nuxt dev 會自動清除）"; fi
else ok "目前沒有執行中的 dev server"; fi

# 7. nuxt docs 快取（首次需對外連線）
if npx --no-install nuxt docs "useAsyncData" --no-open >/dev/null 2>&1; then ok "nuxt docs 可用（文件索引已就緒）"
else warn "nuxt docs 執行失敗：首次需連線下載文件，請確認網路"; fi

# 8. 安裝 Claude Code skill（選用）
SKILL_DIR=".claude/skills/nuxt46-agent-workflow"
if [ "$INSTALL_SKILL" = "1" ]; then
  if [ -f "$SKILL_DIR/SKILL.md" ]; then
    warn "$SKILL_DIR/SKILL.md 已存在，未覆蓋（如需更新請先刪除）"
  else
    mkdir -p "$SKILL_DIR"
    cat > "$SKILL_DIR/SKILL.md" <<'SKILL_EOF'
---
name: nuxt46-agent-workflow
description: 在 Nuxt 4.6+ 專案中查文件、啟動或沿用 dev server、驗證 SSR 修改、處理錯誤畫面貼來的 prompt 時使用。觸發情境：修 Nuxt 頁面 / API bug、查 Nuxt API 用法、需要啟動 nuxt dev、使用者貼上以「Help diagnose this error.」開頭的錯誤內容、改完程式需要驗證。
---
